# ADR-350：独立全景推演厅、突发事件与可拖动时间轴

- 状态：Accepted，Phase 0 已完成
- 日期：2026-08-13

## 背景

现有 `apps/web` 是多路由浅色 SaaS 工作台，适合开发和审计，但无法满足路演大屏的空间叙事、全屏操作、自动播放和单画布交互要求。用户决定保留后端机制，重建独立演示前端，并要求突发事件与可拖动时间轴成为核心能力。

## 决策

1. 新建独立 `apps/presentation`，正式入口为 `/experiments/:id/present`；旧 `apps/web` 在新模块验收前保持可用，不原地重写。
2. 全景推演厅只有一个主画布，通过 HUD、功能坞、浮动 Tab、模态窗、侧滑详情和底部时间轴完成全部操作。
3. 产品包含 `live`、`story`、`compare` 三种模式，分别服务现场操作、章节回放和结果对照。
4. 突发事件是实验设计一级模块。现有五项模板继续支持，目录升级为版本化可扩展注册表；任何新事件必须绑定确定性机制、provenance、Schema 和测试。
5. “伊朗相关冲突升级导致油价上涨”只作为“国际冲突情景下油价上涨”的示例表达，不构成现实战争或油价预测。
6. V1 事件触发边界保持为推演开始前、省份初始行动后、车企初步响应后。晚期触发必须先扩展 Orchestrator 和调用预算。
7. 底部时间轴连续可拖动，但业务状态只在后端冻结帧切换；帧间只补间镜头、颜色、透明度、线条和数字展示，不补算业务结果。
8. 新增 `presentation-timeline-v1`、`presentation-frame-v1`、`presentation-event-marker-v1` 和 `presentation-overlay-record-v1` 只读投影契约。
9. 主地图采用 MapLibre GL JS + deck.gl，现有校验地图为唯一几何来源，并保留 ECharts/SVG 兼容模式。

## 后果

- 路演者可以在一个屏幕中配置事件、推进七轮、拖动回看和讲述 A/B 结果。
- 后端必须提供可验证的历史演示帧，前端不能仅凭 Replay 拼接或重算权威状态。
- 可扩展事件目录不会允许任意自由文本直接进入环境；新增事件的速度受机制和数据门禁约束。
- MapLibre/deck.gl 只有在离线地图、几何一致性、4K 性能和故障降级验证通过后才能成为正式主引擎。
