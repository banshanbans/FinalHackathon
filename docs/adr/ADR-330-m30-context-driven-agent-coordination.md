# ADR-330：M30 上下文驱动的 Agent 自主协作

- 状态：Accepted，Validation Reopened
- 日期：2026-08-13

## 决策

M30 撤销按省份顺序、相邻位置、固定分组或行为阈值生成合作的实现。M29 事实、特征与关系边全部作为 Agent 上下文；现有协作网是软先验，不是资格门禁。

省级调整轮拆为 3A 提议和 3B 响应。两分支全部 3A 冻结后才允许启动任一 3B。Agent 可选择网外对象，但必须输出可追溯的产业、节点、企业信号或政策目标依据。

Orchestrator 只保留 Schema、身份、分支、轮次、信息权限、预算与资源守恒约束。合作只在“提出＋接受＋双方资源合法”时进入确定性环境贡献。Agent 不直接生成 Gap、需求、ROI 或机制贡献。

## Provider 与溯源

产品 Live Provider 使用 `gpt-5.6-luna` 严格结构化输出，允许一次结构化修复。每次调用记录模型、输入哈希、输出哈希、Schema 和 fallback 状态。缓存容器使用中性 `v32-m30-agent-cache-v1`；本地确定性 Provider 只是显式故障接管，不得写入 `v3_2_m30_luna` 命名空间或标记为 Luna 结果。

## 后果

- 完整双分支为 226 次主体调用。
- DecisionTrace 升级为 v2，对外解释为什么、为什么不、改变条件与机会成本，不保存思维链。
- Compare 与 Presentation Summary 只能引用实际运行对象，不得在前端硬编演示链。
- 旧 V3.2 缓存与对象只读保留；M30 全量验收完成前不得宣称 V3.2 重新冻结。
